# ИНСТРУКЦИЯ ДЛЯ ИИ: РАЗРАБОТКА ERP-СИСТЕМЫ (ЦЕМЕНТНОЕ ПРОИЗВОДСТВО)

## 1. СТЕК ТЕХНОЛОГИЙ И СТРУКТУРА ПРОЕКТА

* **Backend:** Node.js, Express, SQLite (с модулем `better-sqlite3` для синхронных и быстрых транзакций).
* **Frontend:** React (Vite), Tailwind CSS, **shadcn.com** (компоненты устанавливаются через shadcn CLI), Lucide React (иконки).
* **Структура директорий проекта:**

```text
/
├── server/
│   ├── database.js       # Инициализация БД, схемы таблиц и логика бэкапов
│   ├── server.js         # Точка входа Express API
│   └── routes/           # API эндпоинты (warehouses, sales, finance, users)
├── client/
│   ├── src/
│   │   ├── components/ui # Компоненты shadcn (Button, Table, Dialog, Input и т.д.)
│   │   ├── pages/        # Страницы (Warehouse, Sales, Finance, Settings)
│   │   ├── App.jsx
│   │   └── main.jsx

```

## 2. ТРЕБОВАНИЯ К БАЗЕ ДАННЫХ И СИСТЕМЕ БЭКАПОВ (BACKEND)

Бэкенд обязан содержать скрипт автоматического и ручного резервного копирования базы данных без остановки сервера.

### Схема базы данных (SQLite):

1. **`products` (Склад / Номенклатура):**
* `id` (INTEGER PRIMARY KEY)
* `name` (TEXT, наименование: цемент М400, М500, тара и т.д.)
* `category` (TEXT)
* `unit` (TEXT, шт, мешок, тонна)
* `stock_quantity` (REAL, текущий остаток)
* `purchase_price` (REAL, закупочная цена)
* `selling_price` (REAL, отпускная цена)


2. **`sales` (Продажи и отгрузки):**
* `id` (INTEGER PRIMARY KEY)
* `date` (TEXT, дата транзакции)
* `client_name` (TEXT)
* `total_amount` (REAL)
* `status` (TEXT: 'Оплачено', 'В долг', 'Доставка')
* `delivery_type` (TEXT: 'Самовывоз', 'Доставка')


3. **`sales_items` (Состав продажи):**
* `id` (INTEGER PRIMARY KEY)
* `sale_id` (INTEGER, FK)
* `product_id` (INTEGER, FK)
* `quantity` (REAL)
* `price` (REAL)


4. **`finances` (Финансы и долги):**
* `id` (INTEGER PRIMARY KEY)
* `date` (TEXT)
* `type` (TEXT: 'Приход', 'Расход')
* `category` (TEXT: 'Продажа цемента', 'Зарплата', 'Логистика')
* `amount` (REAL)
* `description` (TEXT)


5. **`backups_log` (Лог бэкапов):**
* `id` (INTEGER PRIMARY KEY)
* `filename` (TEXT)
* `created_at` (TEXT)



### Обязательный код бэкапа на Node.js (`server/routes/backup.js`):

ИИ должен реализовать эндпоинт для скачивания и создания резервной копии базы данных:

* При вызове `GET /api/backup` бэкенд должен скопировать файл базы данных (`database.sqlite`) в папку `/backups/backup-<TIMESTAMP>.sqlite` и отправить его клиенту как файл для скачивания.

## 3. ТРЕБОВАНИЯ К REST API (NODE.JS / EXPRESS)

Бэкенд должен предоставлять следующие обязательные эндпоинты с валидацией входных данных:

* **Склад:**
* `GET /api/products` — получение списка всех товаров и остатков.
* `POST /api/products` — добавление новой позиции.
* `PUT /api/products/:id` — обновление цены или количества.


* **Продажи:**
* `GET /api/sales` — история продаж.
* `POST /api/sales` — оформление новой продажи (транзакция: уменьшает `stock_quantity` в таблице `products`, создает запись в `sales` и `sales_items`, фиксирует доход в `finances`).


* **Финансы и долги:**
* `GET /api/finances` — список всех финансовых операций.
* `GET /api/finances/debts` — список клиентов с неоплаченными статусами («В долг»).


* **Система:**
* `GET /api/backup` — скачивание файла резервной копии базы данных.

## 4. ТРЕБОВАНИЯ К FRONTEND (REACT + SHADCN.COM)

Интерфейс должен строиться строго с использованием компонентов **shadcn.com**. Никаких кастомных громоздких стилей, только Tailwind CSS классы и готовые примитивы.

### Обязательные страницы и интерфейсы:

1. **Страница «Склад» (`/warehouse`):**
* Таблица (`shadcn Table`) со списком цемента и сопутствующих товаров.
* Кнопка «Добавить товар» открывает `shadcn Dialog` (модальное окно) с формой (название, единица измерения, остаток, цены).


2. **Страница «Продажи и отгрузки» (`/sales`):**
* Форма создания отгрузки: выбор клиента, динамическое добавление товаров из складской базы, указание типа доставки (самовывоз/транспорт).
* Таблица истории отгрузок с фильтрацией по статусам оплаты.


3. **Страница «Финансы и Долги» (`/finance`):**
* Карточки-метрики (`shadcn Card`) в верхней части: Общая выручка, Чистая прибыль, Дебиторская задолженность (долги клиентов).
* Таблица финансовых операций с цветовой индикацией прихода/расхода.


4. **Страница «Настройки / Бэкап» (`/settings`):**
* Кнопка «Создать и скачать резервную копию БД» (`shadcn Button`), которая отправляет запрос на `GET /api/backup` и инициирует скачивание файла бэкапа на компьютер пользователя.

## 5. ПРАВИЛА НАПИСАНИЯ КОДА ДЛЯ ИИ

1. **Никаких заглушек (`// TODO` или `pass`):** Каждый эндпоинт и каждый компонент должны быть полностью написаны с рабочей логикой подключения к SQLite и отрисовки интерфейса.
2. **Обработка ошибок:** На бэкенде оборачивать все операции с базой данных в блоки `try/catch` с откатом транзакций (`ROLLBACK`) при сбое отгрузки. На фронтенде выводить ошибки через `shadcn Toast` или Alert.
3. **Идемпотентность и чистота:** Использовать ES-модули (`import`/`export`) для Node.js (или настроенный CommonJS, но единообразно во всем проекте).
