ПОДРОБНАЯ ИНСТРУКЦИЯ ПО РАБОТЕ И АРХИТЕКТУРЕ ERP-СИСТЕМЫ
1. СКВОЗНОЙ ЖИЗНЕННЫЙ ЦИКЛ ПРИЛОЖЕНИЯ (КАК ЭТО РАБОТАЕТ)
Система работает по классической клиент-серверной архитектуре:

Клиент (React + Vite + shadcn/ui) отправляет HTTP-запросы (JSON) через встроенный fetch или axios на сервер.

Сервер (Node.js + Express) принимает запросы, валидирует входящие параметры, выполняет бизнес-логику и взаимодействует с базой данных.

База данных (SQLite через better-sqlite3) хранит всю информацию в одном файле (database.sqlite) на диске сервера. Все операции (особенно продажи) выполняются строго в рамках транзакций, чтобы предотвратить рассинхронизацию склада и финансов.

2. ПОДРОБНАЯ СХЕМА БАЗЫ ДАННЫХ И ТАБЛИЦ (SQLITE)
Инициализация базы данных происходит автоматически при первом запуске сервера (server/database.js). Создаются следующие таблицы с жесткими связями:

Таблица products (Склад / Номенклатура)
Хранит номенклатуру цемента и сопутствующих товаров.

id INTEGER PRIMARY KEY AUTOINCREMENT

name TEXT NOT NULL — Название (например: "Портландцемент М400", "Мешки пустые")

category TEXT NOT NULL — Категория ("Цемент", "Тара", "Добавки")

unit TEXT NOT NULL — Единица измерения ("кг", "тонна", "мешок", "шт")

stock_quantity REAL NOT NULL DEFAULT 0 — Текущий остаток на складе

purchase_price REAL NOT NULL DEFAULT 0 — Закупочная цена за единицу

selling_price REAL NOT NULL DEFAULT 0 — Отпускная цена за единицу

Таблица sales (Шапка продаж / Отгрузок)
Фиксирует факт продажи клиенту.

id INTEGER PRIMARY KEY AUTOINCREMENT

date TEXT NOT NULL — Дата и время сделки (ISO строка)

client_name TEXT NOT NULL — ФИО клиента или наименование компании-покупателя

total_amount REAL NOT NULL — Итоговая сумма продажи

status TEXT NOT NULL DEFAULT 'Оплачено' — Статус («Оплачено», «В долг», «Частично»)

delivery_type TEXT NOT NULL DEFAULT 'Самовывоз' — Тип отгрузки («Самовывоз», «Доставка транспортом»)

Таблица sales_items (Строки продажи / Состав накладной)
Связывает продажу с конкретными товарами и количеством.

id INTEGER PRIMARY KEY AUTOINCREMENT

sale_id INTEGER NOT NULL — Ссылка на sales.id (FOREIGN KEY CASCADE)

product_id INTEGER NOT NULL — Ссылка на products.id

quantity REAL NOT NULL — Проданное количество

price REAL NOT NULL — Цена продажи за единицу на момент сделки

Таблица finances (Финансовый учет и Касса)
Учитывает все приходы и расходы компании.

id INTEGER PRIMARY KEY AUTOINCREMENT

date TEXT NOT NULL — Дата операции

type TEXT NOT NULL — Тип движения денег ('Приход' или 'Расход')

category TEXT NOT NULL — Категория («Продажа цемента», «Зарплата», «Закупка сырья», «Логистика»)

amount REAL NOT NULL — Сумма операции

description TEXT — Дополнительное описание / примечание

3. ПОДРОБНАЯ ЛОГИКА РАБОТЫ КЛЮЧЕВЫХ API-МАРШРУТОВ (BACKEND)
Все файлы бэкенда лежат в папке server/routes/. Ниже описан детальный алгоритм работы критически важных эндпоинтов:

А. Проведение продажи (POST /api/sales)
Этот процесс обязан выполняться внутри транзакции базы данных (db.transaction()), чтобы избежать сбоев (например, когда деньги зафиксировались, а со склада товар не списался).

Шаг 1 (Валидация): Сервер проверяет, передан ли массив товаров (items) и имя клиента.

Шаг 2 (Проверка склада): Для каждого товара в запросе сервер проверяет текущий остаток в таблице products. Если stock_quantity < requested_quantity, транзакция прерывается с ошибкой 400 Bad Request и текстом: «Недостаточно товара [Название] на складе».

Шаг 3 (Запись шапки): Создается запись в таблице sales, возвращается сгенерированный sale_id.

Шаг 4 (Запись позиций и списание): В цикле для каждого товара:

Создается запись в sales_items.

Выполняется SQL-запрос обновления склада: UPDATE products SET stock_quantity = stock_quantity - ? WHERE id = ?.

Шаг 5 (Фиксация финансов): Если статус продажи не равен «В долг», автоматически создается запись в таблице finances с типом 'Приход', категорией 'Продажа цемента' и суммой равной total_amount.

Шаг 6 (Коммит): Транзакция успешно завершается (COMMIT).

Б. Модуль резервного копирования БД (GET /api/backup)
Реализация надежного бэкапа без остановки работы Express-сервера:

При обращении клиента на /api/backup бэкенд формирует уникальное имя файла на основе временной метки: backup-YYYY-MM-DD_HH-mm-ss.sqlite.

Создается папка /backups (если она еще не существует).

Используя встроенные возможности SQLite (db.backup()), база данных безопасно копируется в файл бэкенда в фоновом режиме.

Сервер отправляет файл пользователю через команду Express res.download(backupFilePath), после чего файл остается на сервере как точка восстановления.

4. ПОДРОБНАЯ ЛОГИКА РАБОТЫ ИНТЕРФЕЙСА (FRONTEND)
Фронтенд строится на React (Vite) с дизайн-системой shadcn/ui. Управление состоянием страниц строится на хуках useState и useEffect, а запросы к API выполняются через вспомогательный модуль fetch.

Структура экранов (UI/UX потоки):
Экран «Склад» (/warehouse):

Отображает данные из GET /api/products в виде таблицы shadcn Table.

Колонки таблицы: Наименование, Категория, Ед. изм., Остаток, Себестоимость, Цена продажи, Действия.

Кнопка «Добавить товар» открывает диалоговое окно shadcn Dialog с формой ввода. При отправке формы данные уходят методом POST /api/products, после чего таблица мгновенно обновляется без перезагрузки страницы.

Экран «Продажи и отгрузки» (/sales):

Содержит форму оформления отгрузки цемента. Пользователь выбирает клиента из выпадающего списка или вводит вручную, указывает тип доставки («Самовывоз» / «Доставка»).

Динамический блок добавления позиций: выбор товара из списка складов и указание нужного количества.

Кнопка «Провести отгрузку» отправляет JSON на POST /api/sales. В случае успеха выводится уведомление (shadcn Toast), а остатки на складе автоматически пересчитываются.

Экран «Финансы и Долги» (/finance):

В верхней части выводится аналитика в карточках shadcn Card:

Общая выручка за период.

Общая сумма дебиторской задолженности (клиенты со статусом «В долг»).

Ниже расположена таблица всех финансовых транзакций с фильтрацией по типу («Приход» / «Расход»).

Экран «Настройки и Бэкап» (/settings):

Содержит карточку управления безопасностью базы данных.

Кнопка «Создать и скачать бэкап базы данных» при клике запускает скачивание файла .sqlite прямо на рабочий стол администратора системы. Это гарантирует 100% сохранность данных при любых сбоях оборудования.
